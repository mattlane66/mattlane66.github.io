The constraint

An answer can be correct and still be bad tutoring.

A generic assistant optimizes for completing the request. A learning product has another job: keep the student moving while preserving the reasoning they are supposed to learn. CodeAI’s current AI Tutor describes that explicitly through Socratic guidance, debugging support, and task-level scaffolding.

The product move

Put the tutor where the thinking happens.

AI Tutor lives inside supported CodeAI labs rather than as a separate destination. In Web Lab, students can ask questions, generate code, request changes, debug, and explore ideas while the website they are building remains in front of them.

Web Lab + AI Tutor

The editor, output, lesson, and tutor become one learning surface.

That matters because the assistant can respond to the actual artifact and task instead of forcing the student to copy context into a generic chat window. The current Web Lab experience supports HTML, CSS, and JavaScript, with AI Tutor built into the workflow.

What I shaped

Curriculum became an action space the model could read.

I translated modular curriculum into an LLM-interpretable action space. The product problem was to make instructional intent legible to the model: what the student is working on, what the lesson is trying to teach, and what kind of intervention is appropriate now.

Lesson objectiveWhat the student should understand—not merely produce.
Task stateWhere the learner is in the activity and what they are trying to do.
Student artifactThe actual code or project state the tutor can respond to.
Instructional boundaryHow much help is appropriate for this task and learner.
Tutoring actionQuestion, hint, explanation, debugging help, reflection, or code support.
The point was not to make the model “know CodeAI” in the abstract. It was to give it enough structured instructional state to choose a useful next move.
The learning loop

The loop mattered more than the answer.

The current Intro to Web Lab lesson makes the intended behavior visible: students start with a vision, let AI produce a first draft, notice the mismatch, investigate HTML/CSS concepts, debug and refine, then return to the original page with better judgment.

01Set a visionStart from something the student wants to make.
02GenerateUse AI to turn the idea into a first working version.
03Notice the gapCompare what appeared with what the student imagined.
04InvestigateAsk, debug, prompt, and learn the concepts that explain the mismatch.
05JudgeAccept, reject, revert, or change the suggestion.
06IterateReturn to the artifact with more understanding than before.

What stayed with me

AI should tighten the feedback loop without making the learner disappear.

The useful question is not “can the model do this?” It is “what should the person understand or decide after the model does its part?” In learning products, that distinction is the product.
